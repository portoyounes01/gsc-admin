# Project documentation map

This folder is the operating manual for the Global Smile Care Dashboard beta.

## Read in this order

1. [`SESSION_CONTEXT.md`](SESSION_CONTEXT.md) — current handoff, completed work, and next step.
2. [`SOFTWARE_DOCUMENTATION.md`](SOFTWARE_DOCUMENTATION.md) — system-wide software reference.
3. [`PROJECT_ANALYSIS.md`](PROJECT_ANALYSIS.md) — what exists, how it is structured, and the main risks.
4. [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md) — the recommended work sequence, with small, verifiable increments.
5. [`PORTAL_PLAN.md`](PORTAL_PLAN.md) — the separate care-centre portal plan.
6. [`PORTAL_DATA_MODEL.md`](PORTAL_DATA_MODEL.md) — ownership, data boundaries, and isolation design before implementation.
7. [`AI_WORKFLOW.md`](AI_WORKFLOW.md) — how to request or perform future edits without spending context or tool credits unnecessarily.

## Documentation rules

- Keep one decision in one place; link to it instead of copying it.
- Add dates to decisions that may change.
- Prefer short, scoped tasks over broad “improve everything” requests.
- Update the analysis only when architecture or operational behavior changes.
- Update the plan when priorities or acceptance criteria change.
